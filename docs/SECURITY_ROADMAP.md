# Depot Security and Compliance Roadmap

## Purpose

This roadmap defines the security, privacy, regulatory and software-assurance work required to move Depot from preview software toward a production-ready inventory and business-operations platform. It is engineering guidance and evidence planning; it does not itself establish legal compliance or certification.

## Objectives

Depot is developed toward applicable requirements and principles from the EU Cyber Resilience Act, GDPR/DSGVO, German GoBD, EN 16931 electronic invoicing, ISO/IEC 27001, ISO/IEC 27034, ISO/IEC 25010, OWASP ASVS/SAMM, WCAG 2.2 AA / EN 301 549 and enterprise/NIS2-influenced supply-chain requirements.

## Guiding principles

1. Security and privacy by design and by default.
2. Least privilege for users, services and database identities.
3. Finalized business records are immutable where historical integrity requires it.
4. Corrections use traceable reversal/correction transactions rather than destructive edits.
5. Security-relevant actions are auditable.
6. Secrets and credentials are not written to logs or exported unintentionally.
7. Production releases have traceable source, dependencies, build and security status.
8. Vulnerabilities have an owner, severity, remediation target and disclosure process.
9. Backup is incomplete without tested recovery.
10. Compliance evidence should be generated by normal engineering processes wherever practical.

# Phase 7 - Software quality and accessibility

**Status: TECHNICAL IMPLEMENTATION COMPLETE — 2026-08-22**

Target: 1.0 and continuous improvement.

Phase 7 repository/CI implementation is complete. The quality workflow now builds with warnings treated as errors and runs the regression suite plus the 100,000-record performance baseline on both Windows Server 2022 and Windows Server 2025. Static accessibility checks are enforced independently. Manual interactive-desktop and real external-database evidence remains a release acceptance activity rather than missing generic application code.

## ISO/IEC 25010 inspired quality gates

- [x] Functional suitability: critical inventory, warehouse, purchasing, sales, administration, security, recovery and invoicing regression suites are executed by CI; the quality matrix additionally executes the regression suite on both supported Windows CI generations.
- [x] Performance efficiency: a 100,000-record SQLite gate enforces measurable insert and paged-query limits.
- [x] Compatibility: build and regression/performance gates execute on Windows Server 2022 and Windows Server 2025 with .NET 10; provider-neutral normalization/configuration is covered by automated tests.
- [x] Interaction capability: shared UI resources and state patterns are required; static accessibility checks protect focus, contrast and non-color status semantics.
- [x] Reliability: rollback, interruption/failure-path, optimistic-concurrency and backup/recovery tests are included in automated regression evidence.
- [x] Security: security supply-chain, security boundary tests and release-integrity checks remain explicit automated release gates.
- [x] Maintainability: locked dependencies, zero-warning builds, documented architecture/coding standards and CI review controls are enforced.
- [x] Flexibility: provider-neutral architecture/configuration is tested; real-provider claims remain deployment acceptance gates.
- [x] Safety: immutable/correction workflows, optimistic concurrency and atomic business/audit persistence prevent reviewed workflows from silently corrupting or misrepresenting business state.

## Accessibility technical baseline

- [x] Establish WCAG 2.2 AA / EN 301 549 inspired desktop engineering requirements in `docs/compliance/ACCESSIBILITY.md`.
- [x] Preserve keyboard focus visuals; CI rejects `FocusVisualStyle={x:Null}`.
- [x] Shared button styles provide visible keyboard focus.
- [x] Core shell icon actions expose automation names.
- [x] Verify core text/status color pairs against a 4.5:1 contrast baseline in CI.
- [x] Ensure connection/operation status information is textual in addition to color.
- [x] Define keyboard, focus-order, automation, Narrator, DPI/scaling and visual-state release acceptance in the accessibility test matrix.

# Release security gate

A production release should not be approved until applicable evidence exists for all of the following:

- [ ] Release build and automated tests pass.
- [ ] Security-relevant tests pass.
- [ ] No unresolved critical vulnerability exists in shipped dependencies or code.
- [ ] High vulnerabilities are remediated or explicitly documented and risk-accepted.
- [ ] SBOM generated and dependency/license review completed.
- [ ] Executable/package signing verified.
- [ ] Upgrade and rollback tested.
- [ ] Backup and restore tested for supported deployment paths.
- [ ] Phase 7 interactive accessibility/compatibility acceptance completed for the release where applicable.
- [ ] Release notes include security-relevant changes and known limitations where appropriate.
- [ ] Compliance documentation affected by the release has been reviewed.
